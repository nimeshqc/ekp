# Enterprise Knowledge Platform — Finalized Features

> **Purpose:** A polished, self-contained demo used to win Upwork bids in the
> *Data processing / vectorization / embeddings ingestion / RAG / knowledge-base chatbot*
> category. It must feel production-grade to a prospect while running comfortably
> inside a **2 vCPU / 4 GB RAM / 80 GB SSD** box.

The scope below is deliberately **narrow but deep**: every listed feature is fully
finished and visibly impressive. Anything not listed is explicitly out of scope for
the demo.

---

## 1. Roles

| Role | Access | How they get in |
|------|--------|-----------------|
| **Admin** (us) | Full admin portal, generates proposal links, sees all usage | Username + password (env-configured) |
| **Prospect** (client) | Single-purpose demo workspace behind a proposal link | Time-limited signed URL, no login |

There is no general end-user signup. A prospect only ever interacts through a
proposal link we generate for them.

---

## 2. Document Ingestion

- **Accepted formats:** `pdf` (text only — no tables, images, or OCR), `txt`, `md`,
  `docx` (text only — no images, tables, or embedded media).
- **Limits (per proposal link):** max **5 documents**, max **25 MB** per document.
- **Pipeline (visible to user, see §7):** parse → clean → chunk → embed → index.
- **In-house embeddings only** — the embedding model runs locally on CPU. No external
  embedding API is ever called.
- **Idempotent & isolated:** each proposal link has its own document namespace; one
  prospect never sees another's data or the default corpus (unless they opt in).

## 3. Two Corpus Modes (prospect's choice on entry)

1. **Bring your own docs** — prospect uploads up to 5 files and queries them.
2. **Pre-ingested default docs** — a curated corpus we ship, so a prospect can try RAG
   instantly with zero setup.

The prospect can switch modes; each mode is a separate, isolated index.

## 4. RAG Query & Response

Every answer returned to the prospect includes:

- **The answer** to the question, generated by the external LLM (Gemini).
- **Source references** — the specific documents and chunks used.
- **Clickable sources** — clicking opens the source file in a new tab with the
  **exact supporting passage highlighted** (see §5).
- **3 suggested follow-up questions**, generated from the answer + context.
- **Streaming output** — tokens stream to the UI as they are generated (SSE).
- **Grounding guarantee** — if the corpus does not contain the answer, the model says
  so instead of hallucinating (enforced via prompt + retrieval-score threshold).

## 5. Source Highlighting

- Clicking a citation opens the source document in a new tab.
- The **cited passage is highlighted** in-place:
  - **PDF** — rendered via PDF.js, highlight drawn over the matched text span.
  - **txt / md / docx** — rendered as HTML, matched passage wrapped in a highlight mark
    and auto-scrolled into view.
- Highlight anchoring uses the chunk's stored character offsets captured at ingestion
  time (no fragile re-search at click time).

## 6. Observability / Stats (shown live in the UI)

**Ingestion stats (per document + aggregate):**
- End-to-end latency, and per-stage latency (parse / chunk / embed / index)
- Chunk count, total tokens processed, total embeddings created
- Embedding model name + vector dimension
- Document size, page/word count

**RAG stats (per query):**
- Retrieval latency, LLM time-to-first-token, total latency
- Top-k retrieved chunks with similarity scores
- LLM input tokens, output tokens, model name
- Estimated cost (derived from token counts)

Stats are a first-class part of the demo — they are what proves competence to a
technical prospect.

## 7. Live Processing Visualization

- Both ingestion and RAG stream their **pipeline stages** to the UI in real time
  (e.g. *Parsing → Chunking (42 chunks) → Embedding → Indexing → Done*).
- Each stage shows status, duration, and key numbers as it completes.
- This turns an otherwise invisible backend process into a persuasive, animated demo.

## 8. Answer Feedback

- **Like / Dislike** control on every answer.
- Optional one-line reason on dislike.
- Feedback is stored against the query and surfaced in the admin dashboard.

## 9. Proposal Link Generation (core differentiator)

Admin generates a **presigned-style proposal URL** per bid:

- **Signed & tamper-proof** token embedded in the URL.
- **Expiry** — link stops working after a set date/time.
- **Usage caps per link** — max ingestions and max RAG queries, set by admin at
  creation time, to prevent abuse of our API keys and compute.
- **Live remaining budget** — the prospect sees how many uploads/queries remain.
- **Revocable** — admin can kill a link instantly.
- One link = one isolated prospect workspace.

## 10. Admin Portal

- **Create / list / revoke** proposal links, with per-link caps and expiry.
- **Dashboard** tracking every ingestion and every RAG query across all links:
  - Which prospect/link, timestamp, tokens, latency, cost, like/dislike.
  - Per-link usage vs. cap, and expiry status.
- **Default corpus management** — (re)ingest the shipped demo documents.

---

## Non-Goals (explicitly out of scope for the demo)

- OCR, table extraction, image/figure understanding, audio/video.
- Multi-tenant billing, SSO, or real user accounts.
- Fine-tuning models or training the embedder.
- Horizontal scaling / HA — this is a single-box demo.
- Editing or re-chunking documents after upload (upload-and-query only).

---

## Success Criteria for the Demo

1. A prospect opens a link and gets a grounded, cited, streamed answer in **seconds**.
2. Every claim in an answer is **traceable to a highlighted source passage**.
3. The stats and live pipeline make the engineering **visible and credible**.
4. It runs stably within **2 vCPU / 4 GB RAM** without external embedding costs.
5. Admin can spin up a safe, capped, expiring link for each new bid in **one click**.
